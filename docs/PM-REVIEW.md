# LeadPilot PRD v1.1 · 产品评审与本次交付范围

> 评审视角：高级产品经理 + 高级工程师 · 评审日期 2026-11-06 · 对象：资料库《PRD-LeadPilot-B2B外贸客户开发工作台-v1.1》

## 结论先行

PRD v1.1 是一份**架构判断正确、工程纪律清楚**的文档，尤其是「模型不打分、模型不生产事实、分数必须可复现」「缺失维度不补零」「退订红线写进代码」三条，直接避开了 B2B 数据产品最常见的死法。可以进入评审。

但它**不能按 10 周 MVP 直接开工**：有 4 项不在研发控制范围内的硬依赖（Google OAuth 验证、CASA 评估、数据源采购、385 家人工标注集），其中标注集的人力在排期表里根本没有出现。

因此本次交付定位为 **M1/M2 客户端可运行基线**：把不依赖外部条件、且最能验证产品假设的部分（五维可解释评分 + 12 态状态机 + 合规红线 + 完整主链路 UI）做成真实可运行、可测试的代码；采集 / 模型 / Gmail 走可插拔适配器与**明确标注**的演示数据。这样第 1 周就能拿去给种子用户看「评分到底敢不敢信」，而不是等到第 10 周才发现产品假设不成立。

## 一、PRD 做对的三件事

| # | 判断 | 为什么对 |
|---|---|---|
| 1 | 模型只做「理解、判定、解释」，检索管道负责事实，代码负责算数 | 用 PersonQA / WebLists / GTM Bench 三组证据证伪了「全交给大模型」。同一客户两次调用差 8–15 分的产品，业务员用一次就再也不信 |
| 2 | 「无记录 ≠ 没进口」，海关数据不可得时做权重转移 | 德国、日本、中东是外贸主战场。给 0 分会让这些市场名单全军覆没——这是同类工具的死因 |
| 3 | 数据最小化优先于写合规文件（11.4.1） | 判断「分销商还是零售商」根本不需要邮箱和联系人姓名。从协议层剔除，合规面和 token 成本同时下降，是最高 ROI 的工程决策 |

## 二、三个需要修正的口径问题（PM 判断）

| # | 问题 | 建议 |
|---|---|---|
| 1 | **PRW 北极星单位矛盾**：1.5 节写「PRW ≥ 5%」，但定义是「单用户每周收到的正向回复数」；12.2 又写「≥ 1.5」 | 统一为 **PRW ≥ 1.5 条/周/人**，5% 是回复率，不是北极星。指标口径不一致会让周会报表对不上 |
| 2 | **验收口径自相矛盾**：9.5 明确批评「抽样 10 家看效果没有统计意义」，但 AC-04 用「人工抽检 50 家 · 客户类型准确率 ≥ 80%」，而 9.5 门槛是 Cohen's Kappa ≥ 0.65 | AC-04 改为在 385 家基准集上分层抽样评估，与 9.5 共用口径；并补充**多标签判定规则**——一家公司同时是 importer + distributor 时，命中其一算对还是全中才算对，不定义就无法验收 |
| 3 | **AC-16 离线能力在 MVP 不自洽**：MVP 只建草稿、不发送，本地「待发队列」没有可同步的目标 | MVP 保留「断网可看已缓存详情 + 可编辑开发信存本地」；「待发队列 / 联网自动同步」移到 V1 与 gmail.send 一起验收 |

## 三、10 周排期的真风险（按关键路径排序）

| 风险 | PRD 里的位置 | 我的判断 |
|---|---|---|
| **385 家基准集标注是人力关键路径，但排期表里没有这两个人** | 13 章排期风险④、9.5.3 | 2 名外贸背景标注员 × 2–3 周 + 第三人裁决，且 PRD 明确「不能让研发兼任」。这不是「加个任务」，是**要招/借两个人**。M0 第 1 周不启动，M2 的「首次基准集回归」必然跳票 |
| Google sensitive scope 验证 2–6 周 | R1 | M0 启动是对的，但要准备「验证未过」的降级路径：Apps Script / SMTP 体验差，MVP 至少要保证「草稿能力」不依赖 Google 审核结论 |
| 数据源采购 2–4 周 + 年度锁价 | R2 | 建议 Q1 先采 3 国，同时把 `DataSourceAdapter` 的降级链做成可配置，避免某家断供时改代码 |
| 邮箱验证器 IP 信誉需养 2–3 周 | 13 章风险③ | 自建 MX + SMTP 省 90% 成本，但新 IP 直接探测会被大面积拒绝。这是**最容易被漏掉的启动项**，M0 就要开始养 |

**排期建议**：把 M0 从「1 周」拆成「第 1 周启动 + 全程并行」——标注、OAuth 申请、数据源合同、IP 预热四条外部链路并行跑，研发不等它们；M1/M2 用 Mock 适配器先把评分与主链路做扎实。这正是本次交付的做法。

## 四、M0 待决策项 · 建议（Q1–Q11）

| # | 决策 | 建议 | 理由 |
|---|---|---|---|
| Q1 | 海关数据源预算 | **A** 先采美/印/越 3 国 | 用真实使用数据验证付费意愿后再扩，避免一次性锁死成本 |
| Q2 | Google 验证路径 | **A** + M0 同步启动 B 的申请 | MVP 只做 sensitive，把 4–8 周的 CASA 移出关键路径 |

| Q4 | 免费版 | **B** 只做 14 天试用 | 采集是实打实花钱的，免费版会带来大量无效服务器成本 |
| Q5 | 非 Gmail 邮箱 | **V1 加 SMTP** | 中国外贸企业大量用腾讯/阿里/网易企业邮箱，仅 Gmail 会砍掉相当部分用户 |
| Q6 | 团队版数据归属 | **B** 数据归企业 | 更符老板诉求，但要设计员工接受度，V2 议题 |

| Q9 | BYOK | **B** 高级选项、成本兜底 | 保留额度制营收上限，给重度/企业客户一条不亏损通道；主推会让轻度用户流失 |
| Q10 | 数据出境默认 | **A + C** | 默认境内 + 企业版强制境内/本地；B 会让企业客户在 IT 审核阶段直接出局 |
| Q11 | 按新成本重算定价 | **L4 单独设更高系数** | 三级路由下 ¥199 含 7.5 个 L2 任务毛利 63% 可接受，但全跑 L4 会吃光毛利 |

## 五、成本与定价复核（9.4）

| 方案 | 单任务成本（L2/200） | ¥199 套餐含 7.5 任务 | 毛利率 | 结论 |
|---|---|---|---|---|
| A 全 DeepSeek 谷时 | ≈ ¥4.9 | 成本 ¥37 | 81% | 可做，但判断质量全压 Flash 档 |
| **B 三级路由** | **≈ ¥9.9** | **成本 ¥74** | **63%** | **目标区间** |
| C 全 GPT-5 | ≈ ¥80 | 成本 ¥600 | −201% | 订阅制不可行 |

**补充意见**：9.4 只算了 token + 搜索费，漏了基础设施固定成本——Playwright 集群、代理池、页面快照对象存储、SMTP 验证 IP 信誉养护、EV 代码签名（$300–600/年）。这些不随任务线性变化，但会吃掉低活跃用户的毛利。建议单列一张「固定成本表」再定价。同理 11.4 说「成本主要是工程纪律，不是钱」偏乐观：DPA 签署、ZDR 通道溢价、V2 本地模型部署都是真金白银，且是企业客户的采购前置条件。

## 七、Go / No-Go 判据

进入 M1 全量开发前，M0 必须同时满足：

1. 至少 2 家数据源合同签订或可用沙箱 Key；
2. Google OAuth 验证申请已提交（不要求通过）；
3. 385 家基准集标注启动，**标注员已到位且不是研发兼任**；
4. EV 代码签名证书采购下单；
5. 用本次交付的基线跑一轮 5–10 名种子用户访谈，确认「评分卡证据链是否被点开」——如果证据链展开率极低，说明产品价值锚点没成立，继续堆功能没有意义。

> 北极星之外的那句实话：这个产品最大的风险不是竞品，是**用户敢不敢按这个分数去发信**。所以第一优先级永远是评分可信度，不是数据量。

## 八、v0.2.0 进展修订（同日续做，保留上文作为 M0 时点判断）

第六节「诚实清单」是首轮交付时的快照。续做后，以下三项从「未实现」变为**真实可验证的代码**，但**Go / No-Go 四条外部判据一条都没解除**：

| 模块 | v0.1.0 | v0.2.0 | 仍缺什么 |
|---|---|---|---|
| F0 LLM 网关 | 规则层真实、provider 未接 | ✅ 服务端真实：路由 / 降级链 / 熔断 / 缓存 / schema+证据校验 / 点数折算 / 审计 / PII 与地域策略 | 真实 Key、DPA/ZDR、BYOK 加密、点数账本持久化、基准集定版 |
| F2 采集编排 | 本地定时器模拟 | ✅ 服务端真实：6 阶段状态机、SSE、游标、暂停/续跑/中止、并发上限 3、硬超时、单源失败显式降级 | 6 类数据源适配器、代理池 + Playwright、Redis/SQLite 持久化（AC-03 未闭环） |
| 9.5 评测 | 未落地 | ✅ 8 项指标 + P0 门禁 + 无样本 `NO_DATA` 保护 | **385 家人工标注集**（人力关键路径，代码替代不了） |
| F6 写信 | 本地确定性模板 | 🟡 网关配 Key 走真实 T1；无 Key 明确 E6005 并回退本地模板 | 30 封真实样本人工复核、T0 锚点抽取 |

**PM 立场不变**：这些进展把「 engineering risk 」往下压了，没有把「 business risk 」往下压哪怕一毫米。第七节的 Go 判据仍然全部成立——尤其是第 3 条（标注员到位）与第 2 条（OAuth 验证申请），它们决定了 10 周排期是否现实。

**新增一条产品红线**：真实编排 + 假候选域名的混合体比纯演示数据更危险。因此任务配置页强制二选一并在执行页常驻说明：云端模式只推真实 SSE 事件，**不写入任何客户记录**。谁把占位域名渲染成「看起来像真的公司」，谁就是把产品最核心的可信度资产卖掉。
